# Архитектура MVP

## 1. Источники данных

Базовый граф строится из OpenStreetMap. Для Киева нужны:

- `highway=footway|path|pedestrian|steps|track`;
- `highway=service|living_street|residential`;
- тротуары, переходы, калитки, проходы сквозь здания;
- `access`, `foot`, `surface`, `smoothness`, `lit`, `incline`;
- геометрия зданий, заборов и закрытых территорий.

OSM не содержит все неформальные тропы и проходы через дворы. Поэтому продукту
нужен механизм пользовательских правок: «проход существует», «калитка закрыта»,
«проход доступен только днем», «зимой непроходимо».

## 2. Подготовка графа

1. Скачать актуальный PBF-экстракт Киева.
2. Оставить потенциально проходимые линии.
3. Разрезать линии в местах пересечений и переходов.
4. Учесть барьеры и ограничения доступа.
5. Добавить ребра между близкими концами дорожек только после геометрической
   проверки, чтобы не строить путь сквозь забор или здание.
6. Сохранить граф в PostgreSQL/PostGIS или в специализированном движке.

Для первого серверного прототипа подойдет PostgreSQL + PostGIS + pgRouting.
Для более высокой производительности можно перейти на GraphHopper или Valhalla
с собственным пешеходным профилем.

## 3. Маршрутизация

Используется A* и обобщенная стоимость вместо чистого расстояния. Профиль должен
иметь пользовательские режимы:

- `Дворы`: максимальное избегание общих дорог;
- `Сбалансированный`: дворы предпочтительны, но без больших крюков;
- `Освещенный`: дополнительный штраф неосвещенным тропам;
- `Доступный`: исключение ступеней, крутых склонов и плохого покрытия.

Пользователю необходимо показывать фактическую длину и объяснение отклонения:
например, «маршрут на 420 м длиннее, но избегает 1,3 км вдоль магистралей».

## 4. API

Минимальный контракт:

```text
POST /route
{
  "from": {"lat": 50.45, "lon": 30.52},
  "to": {"lat": 50.46, "lon": 30.51},
  "profile": "yards"
}
```

Ответ содержит GeoJSON маршрута, длину, ожидаемое время, разбивку типов пути и
предупреждения о неподтвержденных или потенциально закрытых проходах.

## 5. Критические риски

- Неполнота OSM во дворах.
- Закрытые калитки и частные территории.
- Сезонность грунтовых троп.
- Личная безопасность и освещение.
- Ошибочные «соединения» дорожек через стены, железную дорогу или забор.

Запуск на весь Киев стоит делать после пилота в одном районе, ручной проверки
маршрутов и сбора пользовательских исправлений.
